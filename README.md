# LOOP DEFENSE

요청한 디펜스 게임의 플레이 가능한 웹 프로토타입 v0.3입니다. 외부 패키지 없이 Node.js 22 이상에서 실행합니다.

## v0.3 디자인 업데이트

- 이미지 생성으로 만든 캐릭터 10계열과 이펙트 10종을 전장에 적용했습니다. 기존 100종은 계열별 원화에 색상 변형과 등급 오라를 적용합니다.
- 총기·활의 반동, 검·수확자의 돌진·베기, 마법의 부유 시전, 방향 전환과 이동 흔들림을 추가했습니다.
- 생성 이펙트가 발사체로 이동한 뒤 명중 위치에서 확대·회전·페이드됩니다. 중복 서버 이벤트는 한 번만 재생하며 일시정지하면 연출도 멈춥니다.
- 도감·보유 목록·선택 상세를 캐릭터 카드로 바꾸고 메인 배너에도 그림을 적용했습니다.
- 도감의 `공격 모션 보기` 버튼에서 계열별 연출을 즉시 확인할 수 있습니다.
- 원본 파일, 생성 방식, 정확한 프롬프트와 구현 범위는 [assets/GENERATION.md](assets/GENERATION.md)에 기록했습니다.

## v0.2 변경 사항

- 싱글·협동은 **전멸 즉시 또는 60초마다 다음 웨이브**가 출현합니다. 남은 적은 계속 순환하며, 100마리가 쌓이면 패배합니다. 새 웨이브가 시작할 때 60초 카운트다운이 다시 시작됩니다. 100라운드 이후에는 추가 웨이브가 없습니다.
- 싱글의 일시정지·재개와 1/2/3배속을 추가했습니다. 배속은 게임 시간 전체에 적용됩니다(3배속의 게임 내 60초 = 실제 20초). 일시정지 중에는 시간·출현·공격이 멈추며 소환·장착·이동 명령을 정비할 수 있습니다. 이동 명령은 재개 후 실행됩니다. 온라인 협동·대전은 배속과 일시정지를 허용하지 않습니다.
- 새 챔피언은 처음부터 적을 공격할 수 있는 길 안쪽에 소환됩니다. `자동 배치`는 내 챔피언을 길 안쪽 진형으로 이동시킵니다. 준비 화면에서 이동·자동 배치는 즉시 반영됩니다.
- 챔피언마다 유효 피해·보스·낮은 체력·높은 체력 우선순위를 선택할 수 있습니다. 공격에 면역인 적은 피해를 줄 수 있는 적보다 우선하지 않습니다.
- 보유 챔피언 검색, 장비 부위 필터, 합성 가능한 것만 보기, 합성 가능 표시를 추가했습니다. 장비 장착 대상 선택창이 주기적인 상태 갱신 때 초기화되지 않도록 수정했습니다.
- 타이머·진행 막대·다음 웨이브 정보·몬스터 상세·라운드 알림·피해 숫자·계열별 Canvas 아이콘을 추가했습니다. 이동은 서버 상태 사이를 보간해 그립니다.
- 후반 체력 곡선을 라운드당 지수 1.064에서 1.022로 조정하고, 보스 체력 배율을 14배에서 10배로 낮췄습니다. 일반 클래식 100라운드 일반 몬스터는 약 338,339 HP → 6,277 HP입니다. 하드 체력·면역과 협동 체력 배율은 유지합니다.

`node simulate.mjs 42`로 고정 난수 자동 플레이를 재현할 수 있습니다. 시작 60골드와 처치 보상만 사용하고, 소환·합성·상점 강화·자동 배치를 실행하는 단순 전략이 일반 클래식 100라운드에서 3,000마리를 처치하고 클리어했습니다(게임 시간 약 4,456초). 단일 시드의 회귀용 결과이며 모든 조합·랜덤·하드의 난이도가 검증되었다는 뜻은 아닙니다. `npm run balance`는 라운드별 체력 비교표를 출력합니다.

## 실행

```powershell
npm start
```

브라우저에서 http://localhost:3000 을 엽니다. `계정 연결 → 게스트로 시작하기 → 전투 준비 → 챔피언 소환 → 전투 시작` 순서로 플레이합니다. 현재 폴더에서 `node server.mjs`로도 실행할 수 있습니다. 서버가 종료되면 진행 중인 방과 게스트 세션은 사라집니다.

## 구현 범위

- 메인 화면, 게스트 로그인, Google ID 토큰 서명·발급자·대상·만료 검증과 안정적인 Google 사용자 ID

- 1~100라운드, 라운드당 30마리, 10라운드마다 30번째 몬스터를 보스로 대체
- 네모 궤도 순환, 적 100마리 누적 패배, 싱글·협동 전멸 즉시 또는 60초마다 다음 라운드
- 대전에서 한 명이 현재 라운드를 정리하면 모든 생존자에게 다음 웨이브 추가
- 100개 이름의 챔피언(10계열 × 10변형), 40개 장비(4부위 × 10효과), 각각 7등급
- 자동 공격, 사거리 표시, 클릭 선택, 우클릭·방향키 이동, 터치 이동
- 물리·마법 방어 및 면역, 슬로우·방깎 면역, 관통·장비·치명타·다중 공격
- 빙결, 범위 화염, 범위 기절, 바람 공속 버프, 독, 폭발, 처치 성장
- 60골드 시작, 소환/장비 30골드, 2개 합성, 장비 교체 및 해제
- 독립된 챔피언·장비 상점 Lv.1~10, 확률 표시, 도감·검색·등급 조회
- 서버에서 종료 기록을 저장하는 로컬 랭킹 (`data/rankings.json`)

## 확정한 기본 규칙

동일 이름·등급 2개를 사용하면 확정적으로 다음 등급 1개를 얻습니다. 레전더리는 합성하지 않습니다. 합성 재료 챔피언의 장비는 가방으로 돌아옵니다. 각 방어속성은 일치하는 피해를 65% 감소시키며, 해당 계열 완전면역에는 관통이 적용되지 않습니다. 물리와 마법 완전면역은 동시에 부여하지 않습니다. 독은 별도 피해 계열입니다.

협동 일반 처치는 각자 1골드, 보스는 각자 30골드를 지급합니다. 처치 수는 마지막 타격 플레이어에게 귀속합니다. 고등급 스킬은 유니크부터 자동 발동합니다. 100종은 현재 10가지 전투 동작과 생성 캐릭터 원화를 공유하며 변형마다 기본 공격력과 색상이 다릅니다. 몬스터는 아직 Canvas 도형 기반의 임시 그래픽입니다.

협동 맵은 한 변이 1.4배인 월드로 계산합니다. 화면에는 같은 크기로 축소해 표시하며 이동·사거리·범위 효과를 해당 비율로 적용합니다. 싱글·협동은 60초마다 웨이브가 겹칠 수 있으므로 대전과 마찬가지로 100마리 누적 패배가 적용됩니다. 대전은 기존처럼 한 명이 먼저 라운드를 끝낼 때만 다음 웨이브가 발생합니다.

| 등급 | Lv.1 | Lv.10 |
|---|---:|---:|
| 커먼 | 55% | 10% |
| 언커먼 | 25% | 18% |
| 노말 | 12% | 25% |
| 레어 | 5.5% | 24% |
| 유니크 | 1.8% | 14% |
| 에픽 | 0.6% | 7% |
| 레전더리 | 0.1% | 2% |

중간 레벨은 선형 보간합니다. 업그레이드 비용은 현재 레벨 × 40골드입니다. 전체 확률은 100%입니다.

## 여러 명 접속

같은 네트워크의 다른 기기에서 `http://서버PC의내부IP:3000`으로 접속합니다. 각 플레이어는 별도 브라우저 프로필 또는 별도 기기를 사용해야 합니다(같은 프로필 탭은 로그인 쿠키 공유). 방 생성 후 공개 대기실에서 입장합니다. 정원이 모두 차면 방장이 준비를 시작하고, 각자 소환 후 방장이 전투를 시작합니다.

서버는 모든 골드·소환·전투를 계산하고 SSE로 상태를 전달합니다. 브라우저는 행동 요청과 그리기만 수행합니다. 연결 단절 동안 게임은 계속됩니다. 새로고침하면 같은 세션의 방으로 복귀합니다. 명시적 퇴장은 게임을 종료하며 해당 취소 게임을 랭킹에 올리지 않습니다.

현재 인터넷 공개 배포는 하지 않았습니다. 외부 접속에는 호스팅·도메인·HTTPS 설정이 필요합니다. 대규모 동시 접속, 계정 데이터베이스, 운영용 랭킹 무결성, 재접속 유예 정책은 후속 개발 대상입니다. 랜덤·하드·협동·대전 전체의 밸런스는 추가 플레이테스트가 필요합니다. 게임 내 재화는 실제 결제와 연결되지 않습니다.

## Google 로그인 활성화

Google Cloud에서 웹 애플리케이션 OAuth 클라이언트를 만들고 승인된 JavaScript 원본에 `http://localhost:3000`과 실제 배포 원본을 등록합니다. 클라이언트 ID는 공개 설정이며 클라이언트 비밀키를 넣지 않습니다.

```powershell
$env:GOOGLE_CLIENT_ID = '발급받은ID.apps.googleusercontent.com'
npm start
```

HTTPS 프록시 배포 시 `PUBLIC_ORIGIN=https://실제도메인`도 설정합니다. 그러면 세션 쿠키에 Secure가 적용됩니다. Google 공개 JWK로 RS256 토큰 서명을 검증하며, 동일 `sub`는 동일 사용자로 식별됩니다. 구글 콘솔 설정과 실계정 로그인은 아직 검증하지 않았습니다.

참고: [Google ID 토큰 서버 검증 공식 문서](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token)

## 검증

```powershell
npm test
```

전투 엔진 단위 테스트와 별도 포트에서 수행하는 실제 HTTP/SSE 통합 테스트가 포함되어 있습니다. 통합 테스트는 2인·4인 협동 및 대전 방, 방장 권한, 공유 상태, 세션 복귀, 타 출처 차단을 점검합니다.

## 파일

- `server.mjs`: HTTP 서버, 로그인, 대기실, 상태 스트림, 랭킹
- `engine.js`: 카탈로그, 확률, 게임 규칙 및 서버 전투 시뮬레이션
- `app.js`: 화면, Canvas 렌더링, 입력 및 서버 연결
- `gameplay.js`: 배속·일시정지·배치·타겟 우선순위
- `battle-ui.js`: 전투 HUD·인벤토리·장착 상세
- `renderer.js`: 전장·챔피언·피해 효과와 위치 보간
- `style.css`: 반응형 다크 UI
- `engine.test.js`, `gameplay.test.js`, `server.test.js`: 자동화 검증
- `simulate.mjs`, `balance-report.mjs`: 자동 플레이 및 체력 비교
